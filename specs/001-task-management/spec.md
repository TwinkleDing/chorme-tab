# Feature Specification: 任务管理页面

**Feature Branch**: `001-task-management`

**Created**: 2026-05-28

**Status**: Draft

**Input**: User description: "构建一个任务管理页面，任务列表展示的字段有任务名称、任务创建人、紧急程度、任务状态、创建时间，任务可以通过下拉框按紧急程度和任务状态过滤"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看并按条件过滤任务列表 (Priority: P1)

作为用户，我希望在一个页面上看到所有任务的列表，展示任务名称、创建人、紧急程度、状态和创建时间，并能通过下拉框按紧急程度和任务状态筛选，以便快速找到我关心的任务。

**Why this priority**: 这是任务管理页面的核心功能，用户进入页面后的首要操作就是查看和筛选任务。没有这个功能，页面就失去了存在意义。

**Independent Test**: 打开任务管理页面，确认任务列表正确显示所有字段；操作紧急程度下拉框，列表仅显示匹配的任务；操作任务状态下拉框，列表仅显示匹配的任务；组合两个下拉框进行筛选，列表按交集条件过滤。

**Acceptance Scenarios**:

1. **Given** 用户打开任务管理页面, **When** 页面加载完成, **Then** 展示任务列表，每行包含任务名称、创建人、紧急程度、状态和创建时间
2. **Given** 任务列表已加载, **When** 用户从紧急程度下拉框选择"高", **Then** 列表仅显示紧急程度为"高"的任务
3. **Given** 任务列表已加载, **When** 用户从任务状态下拉框选择"进行中", **Then** 列表仅显示状态为"进行中"的任务
4. **Given** 用户已选择紧急程度"高"和状态"待处理", **When** 筛选生效, **Then** 列表仅显示同时满足"高"紧急程度且"待处理"状态的任务
5. **Given** 筛选项已选择, **When** 用户重置/清空筛选条件, **Then** 列表恢复显示全部任务
6. **Given** 没有任务匹配当前筛选条件, **When** 筛选结果为空, **Then** 页面展示空状态提示"没有匹配的任务"

---

### User Story 2 - 管理任务数据（新增/编辑/删除）(Priority: P2)

作为用户，我希望能够新增任务、编辑已有任务的信息、以及删除不再需要的任务，以便维护完整的任务清单。

**Why this priority**: P2 是因为 CRUD 操作是任务管理的基本能力，但与纯查看和筛选相比，用户可以先通过浏览和筛选确认页面有价值，再进一步管理数据。初始版本可以提供 Mock 数据供浏览。

**Independent Test**: 从 P1 列表页面上点击新增按钮，填写表单后提交，列表中应出现新任务；点击已有任务进入编辑，修改字段后保存，列表应更新；点击删除，确认后任务应从列表中移除。

**Acceptance Scenarios**:

1. **Given** 任务列表页面, **When** 用户点击"新增任务"按钮并填写表单提交, **Then** 新任务出现在列表顶部，所有字段正确显示
2. **Given** 任务列表中某条任务, **When** 用户点击编辑并修改任务名称后保存, **Then** 列表中的任务名称更新
3. **Given** 任务列表中某条任务, **When** 用户点击删除并确认, **Then** 该任务从列表中移除
4. **Given** 新增任务表单, **When** 用户提交时必填字段为空, **Then** 表单提示对应字段不能为空

---

### User Story 3 - 紧急程度和状态的可视化区分 (Priority: P3)

作为用户，我希望紧急程度和任务状态有清晰的视觉区分（如颜色标签），以便通过扫视快速掌握任务优先级和当前进度。

**Why this priority**: 可视化增强提升体验，但对于功能完整性来说不是必需的。没有视觉区分时文字信息仍然可用。

**Independent Test**: 查看任务列表中紧急程度列和状态列的样式表现，确认不同值有不同的颜色或图标区分。

**Acceptance Scenarios**:

1. **Given** 任务列表中包含不同紧急程度的任务, **When** 查看紧急程度列, **Then** 高/中/低分别以红/黄/绿颜色标签展示
2. **Given** 任务列表中包含不同状态的任务, **When** 查看状态列, **Then** 不同状态以不同样式标签展示（如待处理=灰色、进行中=蓝色、已完成=绿色）

---

### Edge Cases

- 任务列表为空时展示友好的空状态提示，引导用户新增任务
- 筛选条件组合后结果为空时，展示"没有匹配的任务"提示并附带重置筛选按钮
- 紧急程度和状态的下拉框支持"全部"选项（默认选中），表示不过滤
- 任务名称过长时截断显示（省略号），悬浮展示完整名称
- 创建时间格式统一为 `YYYY-MM-DD HH:mm`

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在任务管理页面中以表格/列表形式展示所有任务，每行包含任务名称、创建人、紧急程度、状态、创建时间
- **FR-002**: 系统 MUST 提供紧急程度下拉筛选框，选项包含"全部"、"高"、"中"、"低"
- **FR-003**: 系统 MUST 提供任务状态下拉筛选框，选项包含"全部"、"待处理"、"进行中"、"已完成"
- **FR-004**: 系统 MUST 支持紧急程度和状态的组合筛选，结果取交集
- **FR-005**: 系统 MUST 筛选结果为空时展示空状态提示"没有匹配的任务"
- **FR-006**: 系统 MUST 支持新增任务（任务名称、创建人、紧急程度、状态为必填）
- **FR-007**: 系统 MUST 支持编辑已有任务的所有字段
- **FR-008**: 系统 MUST 支持删除任务，删除前需二次确认
- **FR-009**: 系统 MUST 将任务数据持久化存储（localStorage），刷新页面后数据不丢失
- **FR-010**: 系统 SHOULD 紧急程度和状态使用彩色标签展示，便于视觉区分
- **FR-011**: 系统 MAY 页面初始化时提供一组示例任务数据，帮助用户快速了解功能

### Key Entities *(include if feature involves data)*

- **TaskItem**: 表示一个任务，包含以下字段：
  - `id`: 唯一标识（UUID 或时间戳）
  - `name`: 任务名称（字符串）
  - `creator`: 创建人（字符串）
  - `urgency`: 紧急程度（枚举：`high` / `medium` / `low`）
  - `status`: 任务状态（枚举：`pending` / `in_progress` / `done`）
  - `createdAt`: 创建时间（ISO 日期字符串）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户进入任务管理页面后，能在 2 秒内看到完整的任务列表（含 50 条以内数据）
- **SC-002**: 用户筛选任务时，筛选结果在 500ms 内更新渲染完成
- **SC-003**: 用户新增/编辑/删除任务操作后，列表在 1 秒内反映最新数据
- **SC-004**: 关闭页面后重新打开，任务数据与关闭前一致（localStorage 持久化验证）
- **SC-005**: 紧急程度和状态下拉框筛选组合后，结果精确匹配筛选条件，无误报漏报

## Assumptions

- 项目使用 Vue 3 + TypeScript + Element Plus + Pinia（基于项目现有技术栈）
- 任务数据存储在 Pinia Store 中，并通过 localStorage 持久化（与现有 `stock.ts`、`img.ts` 模式一致）
- 初始阶段使用内存 Mock 数据，无需后端 API 支持
- 页面通过 Vue Router 添加新路由 `/tasks`，懒加载页面组件
- 表单使用 Element Plus 的 `el-form` + `el-table` 组件构建
- 紧急程度枚举值：`high` / `medium` / `low`；状态枚举值：`pending` / `in_progress` / `done`
- 不涉及用户认证和权限管理，所有用户可见全部任务
